# نموذج البيانات الأولي

هذه مواصفة منطقية مستقلة عن تقنية التنفيذ. النظام مخصص لمستخدم بشري واحد وحساب دخول واحد فقط، دون أدوار أو إدارة مستخدمين متعددين. لا تنشئ هذه الوثيقة جداول فعلية ولا تتصل بقاعدة بيانات.

## 1. الكيانات

### students — الطلاب

| الحقل المنطقي | مطلوب | القاعدة |
|---|---|---|
| id | نعم | معرّف داخلي ثابت وفريد لا يتغير |
| student_number | نعم | رقم تلقائي ثابت وفريد، لا يعتمد على الاسم |
| manual_number | لا | رقم يدوي اختياري وفريد وثابت بعد تخصيصه؛ لا يُعدّل عاديًا ولا يعاد تخصيصه تاريخيًا |
| full_name | نعم | اسم غير فارغ بعد إزالة المسافات الطرفية |
| phone | لا | رقم/نص هاتف اختياري؛ لا يُستخدم وحده لإثبات الهوية |
| notes | لا | ملاحظات الطالب اختيارية |
| status | نعم | active أو suspended؛ مستقلة عن الحذف المنطقي |
| deleted_at | لا | وقت الحذف المنطقي؛ NULL يعني أن السجل غير محذوف منطقيًا |
| created_at | نعم | وقت إنشاء السجل |
| updated_at | نعم | وقت آخر تحديث ناجح |

قواعد:
- لا حذف نهائيًا.
- لا يتغير manual_number بعد تخصيصه في الاستخدام العادي. التصحيح الاستثنائي يحتفظ بالقيمة السابقة في سجل الأرقام المحجوزة ويسجل السبب.
- الحذف المنطقي يضبط deleted_at ولا يحذف سجل الطالب أو تسجيلاته؛ الاستعادة تعيد السجل نفسه.
- البحث يدعم الاسم والرقم التلقائي والرقم اليدوي والهاتف. القوائم العادية تستبعد المحذوفين منطقيًا افتراضيًا؛ ويظل الوصول إليهم متاحًا في عرض تاريخي مميز، ويمكن استعادة السجل نفسه.
- فحص التشابه للتنبيه فقط، وليس للدمج التلقائي.

### courses — الدورات

| الحقل المنطقي | مطلوب | القاعدة |
|---|---|---|
| id | نعم | معرّف داخلي ثابت وفريد |
| course_code | نعم | رمز تلقائي ثابت وفريد |
| name | نعم | اسم غير فارغ؛ يمنع التكرار بين الدورات المفتوحة فقط، ويسمح بتكراره بين الدورات المغلقة |
| start_date | لا | تاريخ اختياري صحيح |
| end_date | لا | تاريخ اختياري صحيح؛ إذا أُدخل التاريخان معًا فلا يسبق end_date تاريخ start_date |
| status | نعم | open أو closed |
| notes | لا | ملاحظات الدورة اختيارية |
| created_at | نعم | وقت إنشاء السجل |
| updated_at | نعم | وقت آخر تحديث ناجح |

قواعد:
- لا حذف نهائيًا؛ الإغلاق لا يمحو التاريخ.
- إغلاق الدورة يمنع التسجيل الجديد ولا يغيّر حالات التسجيلات الحالية.
- تعديل التواريخ لا يغيّر حالات التسجيل تلقائيًا.
- عدد التسجيلات النشطة قيمة محسوبة من جدول التسجيلات، وليس رقمًا يدويًا محفوظًا.

### enrollments — التسجيلات

| الحقل المنطقي | مطلوب | القاعدة |
|---|---|---|
| id | نعم | معرّف ثابت وفريد |
| student_id | نعم | مفتاح أجنبي إلى students.id |
| course_id | نعم | مفتاح أجنبي إلى courses.id |
| registration_date | نعم | تاريخ التسجيل |
| status | نعم | active أو completed أو withdrawn أو cancelled |
| created_at | نعم | وقت إنشاء سجل النظام، حقل داخلي غير معروض للمستخدم |
| updated_at | نعم | وقت آخر تحديث ناجح |

قواعد:
- لا حذف نهائيًا.
- كل student_id وcourse_id يجب أن يشيرا إلى سجل موجود.
- يمنع وجود تسجيلين بالحالة active للطالب نفسه والدورة نفسها. يجب أن يكون المنع مضمونًا في قاعدة البيانات، لا في الواجهة فقط.
- يُسمح بتعدد السجلات التاريخية للطالب والدورة نفسيهما إذا كانت مستقلة وغير نشطة.
- لا يُعاد تنشيط التسجيلات النهائية بالطريقة العادية. بعد اكتمال التسجيل أو الانسحاب أو الإلغاء، يُنشأ عند الحاجة تسجيل جديد مستقل، مع إبقاء السجل السابق كما هو.
- يجب التحقق من أن الطالب active وغير محذوف منطقيًا والدورة open عند إنشاء تسجيل نشط جديد.

## 2. سجل الأرقام المحجوزة

يجب أن يحتفظ النظام بتاريخ دائم للقيم المستخدمة أو المحجوزة لكل من student_number وmanual_number وcourse_code والمعرّفات المستوردة، مع نوع الرقم والسجل الذي خصص له ووقت الحجز وسبب أي تصحيح استثنائي. لا تُحذف الحجوزات عند الحذف المنطقي أو الاستبدال الكامل. عند استعادة نسخة، تُضاف الحجوزات الواردة إلى الحجوزات الموجودة؛ لا يجوز لنسخة قديمة إزالة حجز تاريخي قائم. لا يكفي قيد UNIQUE على القيم الحالية لمنع إعادة الاستخدام التاريخي.

## 3. العلاقات

- طالب واحد يمكن أن يرتبط بعدد من التسجيلات.
- دورة واحدة يمكن أن ترتبط بعدد من التسجيلات.
- التسجيل الواحد يرتبط بطالب واحد ودورة واحدة فقط.
- لا تُحفظ قوائم التسجيلات داخل حقل JSON في سجل الطالب أو الدورة؛ العلاقة ممثلة بسجلات enrollments مستقلة.

## 4. قيود قاعدة البيانات المطلوبة

1. مفتاح أساسي لكل جدول.
2. تفرد id والمعرفات العامة student_number وcourse_code.
3. تفرد manual_number عندما لا تكون القيمة NULL أو فارغة بعد التطبيع.
4. تفرد اسم الدورة المفتوحة فقط وفق سياسة تطبيع معتمدة؛ يسمح بتكرار الاسم بين الدورات المغلقة.
5. قيود تحقق على حالات الطالب والدورة والتسجيل.
6. التحقق من صلاحية التواريخ، بما في ذلك end_date >= start_date.
7. مفاتيح أجنبية للتسجيلات مع منع حذف السجلات المرجعية حذفًا يكسر التاريخ.
8. قيد فريد جزئي يمنع تسجيلًا نشطًا ثانيًا للزوج (student_id, course_id)، إذا كان مدعومًا؛ وإلا فتُستخدم آلية قاعدة بيانات مكافئة وآمنة تحت التزامن. لا يكفي فحص واجهة أو فحص غير ذري.
9. لا يُعتمد على تحقق الواجهة وحده للقيود الحرجة.
10. معالجة التنافس بين طلبين متزامنين بحيث لا يستطيع كلاهما إنشاء التسجيل النشط نفسه.

## 5. قرارات تحتاج تثبيتًا أثناء التصميم التقني

- هل id من نوع UUID أم معرّف آخر؟ المطلوب أن يكون ثابتًا وفريدًا وآمنًا للاستيراد.
- طريقة توليد student_number وcourse_code، وشكل العرض النهائي لكل منهما.
- سياسة تطبيع اسم الدورة للتفرد (مثل المسافات وحالة الأحرف عند انطباقها).
- هل تُخزن التواريخ كنوع DATE، وأوقات الإنشاء/التعديل كطوابع زمنية مع منطقة زمنية.
- الحد الأقصى لطول الاسم والهاتف والملاحظات.
- يجب أن تحافظ آلية إعادة التفعيل على التمييز بين العودة إلى التسجيل نفسه والتسجيل التاريخي المستقل، وألا تؤدي إلى فقد التاريخ أو تكرار النشاط.

لا يُسمح بحسم هذه الخيارات تخمينًا داخل التنفيذ؛ توثّق وتُختبر قبل اعتماد مخطط قاعدة البيانات. المصادقة تخص حسابًا واحدًا فقط، ولا يدخل جدول المستخدمين أو الأدوار ضمن نموذج البيانات الوظيفي الحالي.

## 6. قواعد الواجهة المرتبطة بالنموذج

- الواجهة عربية RTL.
- تُقبل الأرقام الإنجليزية فقط في الحقول الرقمية والتواريخ: 0123456789.
- صيغة التاريخ المرئية والمدخلة YYYY-MM-DD.
- قوائم الطلاب العادية تعرض النشطين افتراضيًا، مع طريقة واضحة للوصول إلى الموقوفين والسجلات التاريخية.
- قوائم الدورات تعرض الحالة والرمز والتاريخ وعدد التسجيلات النشطة المحسوب.
- إدارة التسجيلات متاحة داخل شاشة الطالب فقط؛ لا توجد شاشة تسجيلات مستقلة ولا إدارة تسجيلات داخل شاشة الدورة.
