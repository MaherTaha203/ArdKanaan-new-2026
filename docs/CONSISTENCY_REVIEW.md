## النتائج والتعديلات

1. وُجد تعارض بين قرار عدم حفظ سجلات/تقارير دائمة وبين وثائق تقترح operation_events وتقارير محفوظة. وُحدت السياسة: ملخص مؤقت فقط.
2. وُجد تعارض في سلوك إعادة المحاولة بعد انقطاع الاتصال: لا يمكن ضمان إعادة نتيجة محفوظة دون حفظها. القاعدة الآن: لا إعادة تلقائية للعمليات الحساسة؛ افحص الحالة الفعلية، وأوقف العمليات الحساسة الجديدة إذا بقيت النتيجة غير محسومة.
3. لم يكن واضحًا كيف تبقى بيانات الطالب المصدر بعد الدمج مع منع نسخ حقوله تلقائيًا. تقرر إبقاء سجل المصدر تاريخيًا مع merged_into_student_id وmerged_at وإخفائه من القوائم التشغيلية العادية.
4. نقل student_id وحده كان سيفقد أصل التسجيل التاريخي؛ أضيف original_student_id الثابت، بينما يشير student_id إلى الطالب الأساسي الحالي بعد الدمج.
5. وُضح أن النسخ الاحتياطي يحفظ سجلات الطلاب المدموجين وحقول الدمج وoriginal_student_id.
6. عولج تكرار بعض معرفات اختبارات MER بإعادة تسمية مجموعة الاختبارات القديمة إلى LEG، وأضيفت اختبارات لمصدر الطالب وأصل التسجيل والنسخ الاحتياطي.
7. أزيلت صياغة الحد المفتوح للملاحظات؛ الحد المعتمد 1000 حرف لملاحظات الطالب والدورة والتسجيل، وتُرفض القيم الأطول ولا تُقص.
8. عُدلت مواضع تصف قرارات معتمدة بأنها مبدئية، وأضيف توضيح بأن القرارات النهائية تسود على الصياغات القديمة المتعارضة.

## القواعد المتسقة حاليًا

- النطاق: الطلاب والدورات والتسجيلات والبحث ولوحة المعلومات والنسخ والاستعادة فقط.
- لا حذف نهائيًا للتاريخ ولا إعادة استخدام رقم أو UUID محجوز.
- وجود تسجيل نشط للطالبين في الدورة نفسها يوقف الدمج قبل أي كتابة.
- التسجيلات النهائية تبقى سجلات مستقلة ولا تُدمج أو تُحذف تلقائيًا.
- الدمج يتطلب اختيار الطالب الأساسي ومعاينة التعارضات وتأكيدًا صريحًا وتنفيذًا ذريًا.
- لا تُنسخ حقول الطالب المصدر المختلفة تلقائيًا؛ يبقى سجل المصدر محفوظًا تاريخيًا.
- لا سجل دائم للأحداث أو التقارير. الملخص مؤقت والبيانات الفعلية هي المرجع.
- ZIP غير مشفر. الملفات المطلوبة لا تغيب؛ تُفحص البنية والعلاقات والبصمات. SHA-256 وحده ليس توقيعًا يثبت المصدر.
- حدود الحقول: اسم الطالب 100، اسم الدورة 100، الهاتف 20، الرقم اليدوي 30، وملاحظات الطالب والدورة والتسجيل 1000 حرف.
- لا تمنح الوثائق إذنًا بالتنفيذ أو النشر.

## بوابات تقنية قبل SQL

1. مراجعة مستقلة للقيود والفهارس وRLS وصلاحيات الكتابة ومنع دورات الدمج.
2. إثبات التوليد الذري للأرقام والاستعادة دون إعادة استخدام المحجوز.
3. اختبار القفل والمعاملة عند تزامن الاستعادة والكتابات والنسخ.
4. اختبار ZIP واللقطة المتسقة والبصمات والإصدارات والملفات المطلوبة.
5. إثبات بقاء الحجوزات التاريخية مستقلة عن الصفوف التشغيلية.
6. اختبار انقطاع الاتصال والنتيجة غير المحسومة دون إعادة تلقائية.
7. تهيئة Supabase Auth والمالك الوحيد ومنع التسجيل العام.
8. تشغيل خطة RESTORE_TEST_PLAN كاملة في بيئة معزولة، بما فيها التراجع ومقارنة الحالة قبل العملية وبعدها.
