# خطة اختبارات النسخ الاحتياطي والاستعادة

الحالة: خطة قبول إلزامية قبل الإطلاق. جميع الاختبارات تنفذ على بيئة اختبار معزولة وببيانات اصطناعية، وليس على الإنتاج.

## 1. قواعد التنفيذ

- تُنشأ قاعدة اختبار جديدة أو نسخة مؤقتة معزولة لكل مجموعة اختبارات.
- لا تُستخدم مفاتيح أو بيانات أو موارد إنتاجية.
- يُحفظ وصف الحالة المتوقعة قبل الاختبار، وتُقارن به الحالة الفعلية بعد التنفيذ.
- لا يُعد ظهور رسالة نجاح أو فشل دليلًا كافيًا؛ يجب فحص السجلات والعلاقات والحالات الفعلية.
- لكل اختبار نتيجة قابلة للتكرار، وبيانات إدخال محفوظة، ونتيجة متوقعة، ونتيجة فعلية.

## 2. إنشاء النسخة الاحتياطية

| المعرّف | الاختبار | النتيجة المطلوبة |
|---|---|---|
| BAK-001 | إنشاء نسخة من بيانات طلاب ودورات وتسجيلات مترابطة | تحتوي الملفات المطلوبة والبيانات الوصفية وإصدار المخطط |
| BAK-002 | إنشاء النسخة أثناء وجود عمليات كتابة | النسخة تمثل لقطة متسقة ولا تحتوي علاقات نصف مكتملة |
| BAK-003 | قاعدة فارغة | الملفات المطلوبة موجودة وتحتوي تمثيلًا صريحًا للمجموعات الفارغة |
| BAK-004 | فتح ZIP وفحص محتوياته | القراءة والبنية ناجحتان، وتُرفض الملفات المطلوبة المفقودة |
| BAK-005 | ملف بحجم أو عدد ملفات أو مسارات غير مسموحة | يرفض بأمان قبل الاستخراج أو الكتابة |
| BAK-006 | ملف داخل ZIP بمسار يحاول الخروج من مجلد المعالجة | يُرفض ولا تُكتب ملفات خارج مساحة العمل المؤقتة |
| BAK-007 | ملف يتضمن محتوى يبدو كتعليمات أو شيفرة | يعامل كبيانات فقط ولا يُنفذ |
| BAK-008 | فشل أثناء إنشاء النسخة أو تنزيلها | لا تظهر نسخة على أنها صالحة؛ يظهر سبب الفشل بوضوح |
| BAK-009 | إنشاء ZIP غير مشفر | يظهر تحذير واضح بشأن البيانات الشخصية قبل الإنشاء ولا يُدّعى أن الملف مشفر |
| BAK-010 | إنشاء نسخة مع أرقام سبق استخدامها ثم حذف/استبدال السجلات التشغيلية | تشمل النسخة سجل الأرقام المحجوزة اللازم لمنع إعادة الاستخدام |
| BAK-011 | التحقق من وجود سجل الأرقام المحجوزة | رفض النسخة إذا غاب ملف الحجز المطلوب أو تعارض مع البيانات الوصفية |
| BAK-012 | فحص بنية النسخة الاحتياطية | لا يوجد ملف مخصص لسجل العمليات الحساسة؛ تبقى جميع الملفات المطلوبة للبيانات التشغيلية والحجوزات موجودة وصالحة |

## 3. المعاينة والتحقق قبل التنفيذ

| المعرّف | الاختبار | النتيجة المطلوبة |
|---|---|---|
| PRE-001 | نسخة سليمة | عرض إصدار المخطط والأعداد الفعلية وملخص السجلات للمستخدم دون حفظ تقرير دائم |
| PRE-002 | اختلاف الأعداد الوصفية عن محتويات الملفات | تُحسب الأعداد من البيانات الفعلية ويُعرض الاختلاف |
| PRE-003 | معرفات مكررة داخل ملف | تعارض واضح؛ لا كتابة في البيانات الحالية |
| PRE-004 | تسجيل يشير إلى طالب أو دورة غير موجودة | لا تخمين ولا إنشاء هوية بالاسم؛ يتوقف السجل أو العملية حسب خطة التعارض |
| PRE-005 | أكثر من مرشح لمطابقة تسجيل | إحالة صريحة للمراجعة |
| PRE-006 | رقم يدوي متعارض | يطبق القرار الموثق أو يطلب مراجعة؛ لا دمج للطلاب |
| PRE-007 | إصدار معروف قديم | تحويل إلى نسخة مؤقتة ثم إعادة فحص كل القيود |
| PRE-008 | إصدار مجهول أو تحويل غير آمن | إيقاف قبل الكتابة |
| PRE-009 | معاينة دون تأكيد | لا تتغير أي بيانات حالية |
| PRE-010 | غياب ملف الطلاب أو الدورات أو التسجيلات | رفض النسخة؛ لا يعامل الملف المفقود كمجموعة فارغة |
| PRE-011 | تكرار الرقم اليدوي داخل النسخة | يُعرض تعارض واضح؛ لا تُدمج السجلات ولا يُعاد تخصيص الرقم تلقائيًا |
| PRE-012 | اسم مكرر بين دورتين مفتوحتين بعد التطبيع | يُعرض تعارض يمنع التنفيذ حتى يُحسم |
| PRE-013 | اسم واحد لدورة مفتوحة وأخرى مغلقة | لا يُعد تعارض تفرد؛ يُسمح به وفق القاعدة المعتمدة |
| PRE-014 | تعارض لم يُحسم قبل تأكيد الدمج | لا تبدأ أي كتابة في البيانات الحالية |
| PRE-015 | رقم يدوي سبق تخصيصه لكنه غير موجود في البيانات الحالية | يُرفض إعادة استخدامه اعتمادًا على سجل الأرقام المحجوزة |
| PRE-016 | دورة بلا تاريخ بداية أو نهاية | تُقبل إذا كانت التواريخ اختيارية؛ وإذا وُجد التاريخان يجب أن تكون النهاية لا تسبق البداية |
| PRE-017 | طالب محذوف منطقيًا في النسخة | يُعرض deleted_at والحالة بوضوح، ولا يُخلط الحذف بحالة الإيقاف |
| PRE-018 | تسجيل نشط لطالب موقوف أو دورة مغلقة مع موافقة المستخدم على الاستثناء | لا يُسمح بتجاوز قيد السلامة؛ يُستبعد السجل من الاستيراد النشط أو يُصحح الوضع بعملية منفصلة مصرح بها ثم تعاد المعاينة |

## 4. اختبارات الدمج

تُنفذ اختبارات الدمج على عملية استثنائية تتطلب اختيارًا صريحًا ومعاينة وتأكيدًا، ولا تنشئ تقارير دائمة.

| المعرّف | الاختبار | النتيجة المطلوبة |
|---|---|---|
| MER-001 | سجل حالي غير موجود في النسخة | يبقى كما هو |
| MER-002 | اسم طالب حالي يختلف عن النسخة | لا يستبدل الاسم الحالي تلقائيًا |
| MER-003 | ملاحظات حالية فارغة والنسخة تحتوي ملاحظات | لا تُستبدل الملاحظات الحالية تلقائيًا؛ يُتبع قرار الحقول المحمية |
| MER-004 | رقم يدوي أو هاتف حالي موجود والنسخة فارغة | تُحفظ القيمة الحالية |
| MER-005 | تاريخ أو حالة تسجيل حاليان يختلفان عن النسخة | لا يتغيران تلقائيًا |
| MER-006 | رابط الطالب أو الدورة يختلف في تسجيل مطابق | تعارض للمراجعة، لا تغيير تلقائي |
| MER-007 | تسجيل غير نشط مستقل مع تسجيل نشط للزوج نفسه | لا يُسقط التاريخ المستقل |
| MER-008 | إدخال تسجيل نشط ثانٍ للزوج نفسه | لا يُنشأ الثاني، ويظهر التعارض في الملخص المعروض للمستخدم |
| MER-009 | طالب موقوف مع تسجيل نشط في النسخة | لا تُفعّل الحالة أو يُغيّر وضع الطالب تلقائيًا |
| MER-010 | دورة مغلقة مع تسجيل نشط جديد في النسخة | لا يُستورد كحالة نشطة مخالفة دون قرار صريح |
| MER-011 | لا يوجد تطابق وسجل جديد صالح | يُضاف كسجل جديد بمعرّفه إذا كان متاحًا |
| MER-012 | معرّف التسجيل مستخدم لسجل مختلف | لا يكتب فوق السجل؛ يُعرض التعارض |
| MER-013 | تعارض غير محسوم في السجلات الإلزامية | لا يبدأ التنفيذ إذا كانت الخطة غير آمنة |
| MER-014 | إعادة إرسال طلب دمج بعد انقطاع الاتصال | تُفحص الحالة الفعلية قبل إعادة المحاولة لمنع تكرار الأثر؛ لا يعتمد الحل على سجل عمليات دائم |
| MER-015 | تعارض إلزامي بقي دون حسم في المعاينة | لا يبدأ الدمج ولا تتغير البيانات الحالية |
| MER-022 | تشابه الاسم أو الهاتف دون اختيار صريح للطالبين | لا يحدث دمج تلقائي |
| MER-023 | تنفيذ دمج دون تأكيد صريح بعد المعاينة | يُرفض التنفيذ ولا تتغير البيانات |
| MER-024 | فشل قيد أو كتابة في منتصف عملية الدمج | تتراجع كل تغييرات الدمج؛ لا تبقى كتابة جزئية |
| MER-025 | دمج ناجح | تُعرض النتيجة الحالية للمستخدم دون حفظ تقرير دائم |
| MER-026 | محاولة الدمج مع تعارض إلزامي غير محسوم | تتوقف العملية قبل أي كتابة |
| MER-027 | لا يحدد المستخدم الطالب الأساسي الذي سيبقى | لا يبدأ الدمج ولا تتغير البيانات |
| MER-028 | النظام يحاول اختيار الطالب الأساسي تلقائيًا | لا يُسمح بالاختيار التلقائي؛ يلزم اختيار المستخدم |
| MER-029 | نقل تسجيلات الطالب الآخر إلى الأساسي يسبب تسجيلًا نشطًا مكررًا | يتوقف الدمج قبل الكتابة ويعرض التعارض |
| MER-030 | نقل تسجيلات الطالب الآخر مع روابط سليمة ودون تكرار نشط | تُنقل التسجيلات وفق المعاينة والتأكيد، مع الحفاظ على التاريخ والمعرفات وفق القواعد المعتمدة |
| MER-031 | دمج طالب ثم محاولة تخصيص رقمه التلقائي لطالب جديد | يُرفض التخصيص؛ يبقى الرقم محجوزًا تاريخيًا بصورة دائمة |
| MER-032 | استعادة أو استبدال كامل بعد دمج طالب | يبقى رقم الطالب المدموج محجوزًا ولا يعاد استخدامه |
| MER-033 | التحقق من رقم الطالب الأساسي بعد الدمج | يبقى الرقم الأساسي دون تغيير، ولا يعاد ترقيم الطالب أو التسجيلات التاريخية |
| MER-034 | دمج طالب ثم محاولة تخصيص رقمه اليدوي لطالب آخر | يُرفض التخصيص؛ يبقى الرقم اليدوي محجوزًا تاريخيًا |
| MER-035 | اختلاف حالة أحرف أو أصفار بادئة في رقم يدوي محجوز بعد الدمج | يطبق التطبيع نفسه ويُرفض أي تخصيص مكافئ للقيمة المحجوزة |
| MER-036 | استعادة أو استبدال كامل بعد دمج طالب يحمل رقمًا يدويًا | يبقى الرقم اليدوي محجوزًا ولا يعاد استخدامه |
| MER-016 | سجل يُستثنى بموافقة صريحة قبل التنفيذ | يظهر الاستثناء وسببه في الخطة والملخص المعروض للمستخدم؛ لا يُستثنى أي سجل بصمت |
| MER-017 | رقم يدوي لطلاب موقوفين أو نشطين | يبقى فريدًا في جميع الحالات ولا يعاد تخصيصه |
| MER-018 | فتح دورة مغلقة واسمها يطابق دورة مفتوحة | يمنع الفتح حتى يُحل تعارض الاسم المفتوح |
| MER-019 | محاولة إعادة تخصيص رقم يدوي سبق استخدامه لطالب آخر | تُرفض العملية ويظل الرقم غير قابل لإعادة الاستخدام وفق سجل الأرقام المحجوزة |
| MER-020 | محاولة إعادة تنشيط تسجيل نهائي | تُرفض؛ يتطلب التسجيل الجديد إنشاء سجل مستقل مع إبقاء القديم |
| MER-021 | استعادة طالب محذوف منطقيًا | يُستعاد سجل الطالب نفسه دون إنشاء تسجيلات جديدة تلقائيًا |
| MER-022 | محاولة تعديل الرقم اليدوي بعد تخصيصه | تُرفض في الاستخدام العادي؛ التصحيح الاستثنائي يسجل القيمة القديمة والسبب |
| MER-023 | محاولة تنفيذ عملية حساسة دون جلسة مصادقة صالحة | تُرفض العملية من جهة الخادم ولا تتغير البيانات |
| MER-024 | التحقق من أن النظام لا ينشئ حسابات أو أدوارًا إضافية من النسخة | لا تتغير إعدادات المصادقة ولا ينشأ مستخدم ثانٍ |

## 5. اختبارات الاستبدال الكامل

| المعرّف | الاختبار | النتيجة المطلوبة |
|---|---|---|
| REP-001 | نسخة صالحة وخطة معتمدة | الاستبدال يقتصر على الطلاب والدورات والتسجيلات |
| REP-002 | إلغاء المستخدم قبل التأكيد النهائي | لا تغيير في البيانات |
| REP-003 | تعذر إنشاء نسخة احتياطية من الحالة الحالية | منع الاستبدال |
| REP-004 | النسخة الاحتياطية السابقة غير قابلة للقراءة أو غير متسقة | منع الاستبدال |
| REP-005 | محاولة تعديل بيانات المصادقة أو الأسرار أو إعدادات الأمان عبر الحزمة | لا يُطبق أي تغيير أمني |
| REP-006 | محاولة التحويل التلقائي إلى الدمج بعد فشل الاستبدال | ممنوعة؛ يلزم بدء عملية جديدة بوضع صريح |
| REP-007 | نجاح الاستبدال | تحقق من الأعداد والمعرفات والعلاقات والحالات ومولدات المعرفات |
| REP-008 | استبدال ببيانات فارغة صريحة وصالحة | لا يقبل إلا بعد تحذير وتأكيد صريحين؛ لا تُعامل الملفات المفقودة كفارغة |
| REP-009 | استبدال كامل مع سجل أرقام محجوزة تاريخي | تُستبدل البيانات التشغيلية فقط وتبقى حجوزات الأرقام التاريخية فعالة |
| REP-010 | محاولة استخدام النسخة لتغيير حساب الدخول الوحيد أو بيانات المصادقة | لا تتغير المصادقة أو الأسرار أو إعدادات الأمان |
| REP-011 | استعادة نسخة أقدم لا تتضمن كل الحجوزات الحالية | تبقى الحجوزات الحالية كما هي وتُضاف إليها الحجوزات الواردة؛ لا يُحذف أي حجز تاريخي |
| REP-012 | النظام سبق أن خصص `ST-000250`، والنسخة القديمة تنتهي عند `ST-000180` | لا ينخفض مولد الطلاب ولا يعاد تخصيص `ST-000181` إلى `ST-000250`؛ يستمر التوليد من موضع آمن أعلى من كل القيم المحجوزة |
| REP-013 | قيمة واردة تتعارض مع حجز تاريخي حالي، أو يتعذر تحديد موضع مولد آمن | تتوقف المعاينة/الاستعادة قبل أي كتابة؛ لا إعادة ترقيم أو تخطٍّ صامت، ويظل الوضع الحالي دون تغيير |
| REP-014 | استبدال كامل يحذف سجلات تشغيلية كانت UUIDs الخاصة بها محجوزة | تبقى حجوزات UUIDs الطلاب والدورات التاريخية محفوظة ومستقلة عن السجلات التشغيلية |
| REP-015 | نسخة تستعيد UUID الأصلي لسجل تاريخي ويمكن إثبات الهوية | يستعاد السجل بهويته الأصلية دون إنشاء هوية بديلة أو حجز مكرر |
| REP-016 | نسخة واردة تحتوي UUID محجوزًا لكيان مختلف أو لا يمكن إثبات هويته | تتوقف العملية قبل أي كتابة؛ لا إعادة ربط أو استبدال UUID بصمت |
| REP-017 | استعادة أو استبدال كامل | لا يتطلب التنفيذ جدولًا دائمًا لسجل العمليات؛ تُعرض نتيجة العملية الحالية، وتبقى الحجوزات التاريخية مستقلة ومحفوظة |

## 6. اختبارات الفشل والتراجع

| المعرّف | الاختبار | النتيجة المطلوبة |
|---|---|---|
| ROL-001 | فشل قبل أول كتابة | البيانات الحالية مطابقة تمامًا لما قبل العملية |
| ROL-002 | فشل بعد إدخال بعض السجلات داخل المعاملة | كل الكتابات تتراجع |
| ROL-003 | فشل بعد تحديث سجلات وقبل إدخال التسجيلات | لا تبقى تحديثات جزئية |
| ROL-004 | خرق قيد مفتاح أجنبي أثناء التنفيذ | تراجع كامل وفق سياسة العملية |
| ROL-005 | خرق قيد التفرد أثناء التنفيذ | لا بيانات جزئية ولا نجاح زائف |
| ROL-006 | انقطاع اتصال العميل أثناء التنفيذ | التحقق من حالة العملية قبل أي إعادة محاولة |
| ROL-007 | النقر المتكرر على زر التنفيذ | لا تنفذ العملية مرتين |
| ROL-008 | تعذر عرض ملخص العملية بعد نجاح أو فشل الكتابة | لا يُعلن نجاح غير متحقق؛ وتظل نتيجة البيانات الفعلية هي المرجع، دون حفظ تقرير دائم |
| ROL-009 | فشل التراجع نفسه أو تعذر التحقق منه | حالة غير محسومة واضحة، وإيقاف العمليات الجديدة حتى التحقيق |
| ROL-010 | مقارنة لقطة البيانات قبل وبعد فشل التنفيذ | تطابق تام في نطاق البيانات الذي كان يجب التراجع عنه |
| ROL-011 | فشل استعادة البيانات التشغيلية | تتراجع التغييرات التشغيلية كاملة دون حذف سجل الأرقام المحجوزة أو إعداد الأمان |
| ROL-012 | انقطاع الاتصال أثناء الاستعادة أو بعد إرسال طلب التنفيذ | تُفحص الحالة الفعلية قبل إعادة المحاولة؛ لا يتكرر الأثر، ولا تُعلن نتيجة نجاح غير متحققة، دون الاعتماد على سجل أحداث دائم |

## 7. تحقق ما بعد التنفيذ

بعد أي عملية ناجحة، يجب التحقق من:
- عدم وجود معرّفات مكررة.
- عدم وجود مفاتيح أجنبية مفقودة.
- عدم وجود أكثر من تسجيل نشط للطالب نفسه في الدورة نفسها.
- عدم تغيير الحقول المحمية أو روابط التسجيلات المطابقة دون قرار موثق.
- صحة أعداد السجلات بناءً على قاعدة البيانات الفعلية.
- اتساق مولدات المعرّفات مع القيم المستوردة.
- وجود نتيجة لكل سجل: أضيف، حُدث وفق قاعدة مسموحة، أُصلح وفق قاعدة معلنة، تُرك وفق قاعدة معلنة، أو يتطلب مراجعة.
- أن الملخص المعروض يطابق النتيجة الفعلية ولا يعلن نجاحًا كاملًا مع وجود تعارض إلزامي.

## 8. بوابة الإطلاق

لا يُسمح بالإطلاق إذا:
- فشل أي اختبار مطلوب.
- لم يمكن إثبات التراجع الكامل عند الفشل.
- بقيت علاقات مفقودة أو معرفات متعارضة أو تسجيلات نشطة مكررة.
- كانت نتيجة عملية بعد انقطاع الاتصال مجهولة.
- كان الملخص المعروض غير متسق مع البيانات الفعلية.
- لم ينجح اختبار دورة كاملة: إنشاء نسخة، تنزيلها، معاينتها، استعادتها في بيئة معزولة، ثم مقارنة النتيجة المتوقعة بالحالة الفعلية.


## 9. حالات اختبار إضافية لمخطط البيانات المقترح

الحالات التالية توسّع الخطة ولا تعني أن التنفيذ بدأ:

| المعرّف | الحالة | النتيجة المطلوبة |
|---|---|---|
| SCH-001 | رقم طالب أو رمز دورة مولد يتزامن مع طلب آخر | لا تتكرر القيمة؛ كل سجل ناجح له حجز مطابق. |
| SCH-002 | إعادة استخدام رقم يدوي حُجز لطالب حُذف منطقيًا أو صُحح رقمه | يُرفض الرقم المحجوز تاريخيًا. |
| SCH-003 | استبدال كامل ببيانات أقدم لا تتضمن حجوزات حالية | تبقى جميع الحجوزات الحالية، وتضاف الحجوزات الواردة غير المتعارضة فقط. |
| SCH-004 | تعارض حجز وارد مع قيمة محجوزة حاليًا | لا تخصيص تلقائي ولا كتابة جزئية؛ يظهر تعارض صريح. |
| SCH-013 | استعادة نسخة أقدم بعد إنشاء أرقام طلاب أو رموز دورات أعلى منها | لا تنخفض المولدات؛ لا يعاد استخدام أي رقم/رمز سبق حجزه، ويُتحقق من الموضع الفعلي للمولد بعد العملية. |
| SCH-014 | حذف أو استبدال طالب/دورة له UUID محجوز | يبقى UUID محجوزًا ولا يمكن تخصيصه لسجل جديد. |
| SCH-015 | استعادة سجل بهويته الأصلية باستخدام UUID محجوز | يسمح فقط إذا أثبتت قواعد المطابقة أنها الهوية التاريخية نفسها؛ لا ينشأ حجز مكرر ولا يتغير الارتباط بصمت. |
| SCH-016 | محاولة استيراد UUID محجوز لكيان مختلف أو بهوية غير قابلة للإثبات | رفض العملية قبل الكتابة مع تقرير تعارض واضح. |
| SCH-005 | محاولة إنشاء تسجيل نشط لطالب موقوف/محذوف أو دورة مغلقة | ترفضها قاعدة البيانات حتى مع تجاوز فحوص الواجهة. |
| SCH-006 | طلبان متزامنان لتسجيل الطالب نفسه في الدورة نفسها | ينجح واحد فقط. |
| SCH-007 | محاولة تحويل تسجيل نهائي إلى active عبر API مباشرة | تُرفض عبر مسار الكتابة المحمي. |
| SCH-008 | جلسة مستخدم غير مالك أو طلب مجهول | لا قراءة ولا كتابة لبيانات النظام ولا تعديل إعداد المالك. |
| SCH-009 | العميل يحاول تعديل/حذف سجل الحجوزات أو إعداد الأمان | ترفض الصلاحيات العملية. |
| SCH-010 | فشل وسط استبدال البيانات التشغيلية | تتراجع بيانات الطلاب والدورات والتسجيلات كاملة، ولا تُمحى الحجوزات أو إعداد الأمان. |
| SCH-011 | إعادة إرسال request_id بعد انقطاع الاتصال | تُعاد النتيجة المسجلة أو حالة غير محسومة؛ لا يتكرر الأثر. |
| SCH-012 | ملف ZIP يفتقد ملفًا مطلوبًا أو يحتوي مسارًا غير آمن أو إصدارًا غير مدعوم | يُرفض قبل أي كتابة. |

يجب تنفيذ هذه الحالات لاحقًا في بيئة معزولة، بعد اعتماد المخطط وكتابة اختبارات آلية مناسبة. لا تُعتبر مراجعة الوثائق وحدها إثباتًا لسلامة قاعدة بيانات فعلية.

| MER-037 | دمج طالبين لكل منهما تسجيل نشط في الدورة نفسها | يتوقف الدمج قبل أي كتابة ويطلب حسمًا صريحًا؛ تبقى السجلات كما هي |
| MER-038 | وجود تسجيلات نهائية متشابهة أو تعارضات تسجيلات أخرى أثناء الدمج | لا تُغيّر التسجيلات تلقائيًا؛ تُعرض التعارضات ويُوقف التنفيذ عند الحاجة إلى حسم |
| MER-039 | محاولة تنفيذ الدمج دون حسم تعارض التسجيل النشط | تُرفض العملية ذريًا ولا يحدث أي تغيير جزئي |
