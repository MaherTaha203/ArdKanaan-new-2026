# خطة اختبارات النسخ الاحتياطي والاستعادة

الحالة: خطة قبول إلزامية قبل الإطلاق. جميع الاختبارات تنفذ على بيئة اختبار معزولة وببيانات اصطناعية، وليس على الإنتاج.

## 1. قواعد التنفيذ

- تُنشأ قاعدة اختبار جديدة أو نسخة مؤقتة معزولة لكل مجموعة اختبارات.
- لا تُستخدم مفاتيح أو بيانات أو موارد إنتاجية.
- يُحفظ وصف الحالة المتوقعة قبل الاختبار، وتُقارن به الحالة الفعلية بعد التنفيذ.
- لا يُعد ظهور رسالة نجاح أو فشل دليلًا كافيًا؛ يجب فحص السجلات والعلاقات والحالات الفعلية.
- لكل اختبار نتيجة قابلة للتكرار، وبيانات إدخال محفوظة، ونتيجة متوقعة، ونتيجة فعلية.

## 2. إنشاء النسخة الاحتياطية

| المعرّف | الاختبار | النتيجة المطلوبة |
|---|---|---|
| BAK-001 | إنشاء نسخة من بيانات طلاب ودورات وتسجيلات مترابطة | تحتوي الملفات المطلوبة والبيانات الوصفية وإصدار المخطط |
| BAK-002 | إنشاء النسخة أثناء وجود عمليات كتابة | النسخة تمثل لقطة متسقة ولا تحتوي علاقات نصف مكتملة |
| BAK-003 | قاعدة فارغة | الملفات المطلوبة موجودة وتحتوي تمثيلًا صريحًا للمجموعات الفارغة |
| BAK-004 | فتح ZIP وفحص محتوياته | القراءة والبنية ناجحتان، وتُرفض الملفات المطلوبة المفقودة |
| BAK-005 | ملف بحجم أو عدد ملفات أو مسارات غير مسموحة | يرفض بأمان قبل الاستخراج أو الكتابة |
| BAK-006 | ملف داخل ZIP بمسار يحاول الخروج من مجلد المعالجة | يُرفض ولا تُكتب ملفات خارج مساحة العمل المؤقتة |
| BAK-007 | ملف يتضمن محتوى يبدو كتعليمات أو شيفرة | يعامل كبيانات فقط ولا يُنفذ |
| BAK-008 | فشل أثناء إنشاء النسخة أو تنزيلها | لا تظهر نسخة على أنها صالحة؛ يظهر سبب الفشل بوضوح |
| BAK-009 | إنشاء ZIP غير مشفر | يظهر تحذير واضح بشأن البيانات الشخصية قبل الإنشاء ولا يُدّعى أن الملف مشفر |

## 3. المعاينة والتحقق قبل التنفيذ

| المعرّف | الاختبار | النتيجة المطلوبة |
|---|---|---|
| PRE-001 | نسخة سليمة | عرض إصدار المخطط والأعداد الفعلية وملخص السجلات |
| PRE-002 | اختلاف الأعداد الوصفية عن محتويات الملفات | تُحسب الأعداد من البيانات الفعلية ويُعرض الاختلاف |
| PRE-003 | معرفات مكررة داخل ملف | تعارض واضح؛ لا كتابة في البيانات الحالية |
| PRE-004 | تسجيل يشير إلى طالب أو دورة غير موجودة | لا تخمين ولا إنشاء هوية بالاسم؛ يتوقف السجل أو العملية حسب خطة التعارض |
| PRE-005 | أكثر من مرشح لمطابقة تسجيل | إحالة صريحة للمراجعة |
| PRE-006 | رقم يدوي متعارض | يطبق القرار الموثق أو يطلب مراجعة؛ لا دمج للطلاب |
| PRE-007 | إصدار معروف قديم | تحويل إلى نسخة مؤقتة ثم إعادة فحص كل القيود |
| PRE-008 | إصدار مجهول أو تحويل غير آمن | إيقاف قبل الكتابة |
| PRE-009 | معاينة دون تأكيد | لا تتغير أي بيانات حالية |
| PRE-010 | غياب ملف الطلاب أو الدورات أو التسجيلات | رفض النسخة؛ لا يعامل الملف المفقود كمجموعة فارغة |
| PRE-011 | تكرار الرقم اليدوي داخل النسخة | يُعرض تعارض واضح؛ لا تُدمج السجلات ولا يُعاد تخصيص الرقم تلقائيًا |
| PRE-012 | اسم مكرر بين دورتين مفتوحتين بعد التطبيع | يُعرض تعارض يمنع التنفيذ حتى يُحسم |
| PRE-013 | اسم واحد لدورة مفتوحة وأخرى مغلقة | لا يُعد تعارض تفرد؛ يُسمح به وفق القاعدة المعتمدة |
| PRE-014 | تعارض لم يُحسم قبل تأكيد الدمج | لا تبدأ أي كتابة في البيانات الحالية |

## 4. اختبارات الدمج

| المعرّف | الاختبار | النتيجة المطلوبة |
|---|---|---|
| MER-001 | سجل حالي غير موجود في النسخة | يبقى كما هو |
| MER-002 | اسم طالب حالي يختلف عن النسخة | لا يستبدل الاسم الحالي تلقائيًا |
| MER-003 | ملاحظات حالية فارغة والنسخة تحتوي ملاحظات | لا تُستبدل الملاحظات الحالية تلقائيًا؛ يُتبع قرار الحقول المحمية |
| MER-004 | رقم يدوي أو هاتف حالي موجود والنسخة فارغة | تُحفظ القيمة الحالية |
| MER-005 | تاريخ أو حالة تسجيل حاليان يختلفان عن النسخة | لا يتغيران تلقائيًا |
| MER-006 | رابط الطالب أو الدورة يختلف في تسجيل مطابق | تعارض للمراجعة، لا تغيير تلقائي |
| MER-007 | تسجيل غير نشط مستقل مع تسجيل نشط للزوج نفسه | لا يُسقط التاريخ المستقل |
| MER-008 | إدخال تسجيل نشط ثانٍ للزوج نفسه | لا يُنشأ الثاني، ويظهر التعارض في التقرير |
| MER-009 | طالب موقوف مع تسجيل نشط في النسخة | لا تُفعّل الحالة أو يُغيّر وضع الطالب تلقائيًا |
| MER-010 | دورة مغلقة مع تسجيل نشط جديد في النسخة | لا يُستورد كحالة نشطة مخالفة دون قرار صريح |
| MER-011 | لا يوجد تطابق وسجل جديد صالح | يُضاف كسجل جديد بمعرّفه إذا كان متاحًا |
| MER-012 | معرّف التسجيل مستخدم لسجل مختلف | لا يكتب فوق السجل؛ يُعرض التعارض |
| MER-013 | تعارض غير محسوم في السجلات الإلزامية | لا يبدأ التنفيذ إذا كانت الخطة غير آمنة |
| MER-014 | تشغيل الدمج مرتين بالطلب نفسه | لا تُنشأ سجلات مكررة؛ يُستعلم عن نتيجة العملية السابقة |
| MER-015 | تعارض إلزامي بقي دون حسم في المعاينة | لا يبدأ الدمج ولا تتغير البيانات الحالية |
| MER-016 | سجل يُستثنى بموافقة صريحة قبل التنفيذ | يظهر الاستثناء وسببه في الخطة والتقرير؛ لا يُستثنى أي سجل بصمت |
| MER-017 | رقم يدوي لطلاب موقوفين أو نشطين | يبقى فريدًا في جميع الحالات ولا يعاد تخصيصه |
| MER-018 | فتح دورة مغلقة واسمها يطابق دورة مفتوحة | يمنع الفتح حتى يُحل تعارض الاسم المفتوح |
| MER-019 | محاولة إعادة تخصيص رقم يدوي سبق استخدامه لطالب آخر | تُرفض العملية ويظل الرقم غير قابل لإعادة الاستخدام وفق سجل الأرقام المحجوزة |

| REP-005 | محاولة تعديل حساب أو صلاحية أو إعداد أمان عبر الحزمة | لا يُطبق أي تغيير أمني |
| REP-006 | محاولة التحويل التلقائي إلى الدمج بعد فشل الاستبدال | ممنوعة؛ يلزم بدء عملية جديدة بوضع صريح |
| REP-007 | نجاح الاستبدال | تحقق من الأعداد والمعرفات والعلاقات والحالات ومولدات المعرفات |
| REP-008 | استبدال ببيانات فارغة صريحة وصالحة | لا يقبل إلا بعد تحذير وتأكيد صريحين؛ لا تُعامل الملفات المفقودة كفارغة |

| ROL-002 | فشل بعد إدخال بعض السجلات داخل المعاملة | كل الكتابات تتراجع |
| ROL-003 | فشل بعد تحديث سجلات وقبل إدخال التسجيلات | لا تبقى تحديثات جزئية |
| ROL-004 | خرق قيد مفتاح أجنبي أثناء التنفيذ | تراجع كامل وفق سياسة العملية |
| ROL-005 | خرق قيد التفرد أثناء التنفيذ | لا بيانات جزئية ولا نجاح زائف |
| ROL-006 | انقطاع اتصال العميل أثناء التنفيذ | التحقق من حالة العملية قبل أي إعادة محاولة |
| ROL-007 | النقر المتكرر على زر التنفيذ | لا تنفذ العملية مرتين |
| ROL-008 | فشل إنشاء التقرير بعد نجاح أو فشل الكتابة | لا يُعلن نجاح غير متحقق؛ تحفظ نتيجة العملية بطريقة موثوقة |
| ROL-009 | فشل التراجع نفسه أو تعذر التحقق منه | حالة غير محسومة واضحة، وإيقاف العمليات الجديدة حتى التحقيق |
| ROL-010 | مقارنة لقطة البيانات قبل وبعد فشل التنفيذ | تطابق تام في نطاق البيانات الذي كان يجب التراجع عنه |

## 7. تحقق ما بعد التنفيذ

بعد أي عملية ناجحة، يجب التحقق من:
- عدم وجود معرّفات مكررة.
- عدم وجود مفاتيح أجنبية مفقودة.
- عدم وجود أكثر من تسجيل نشط للطالب نفسه في الدورة نفسها.
- عدم تغيير الحقول المحمية أو روابط التسجيلات المطابقة دون قرار موثق.
- صحة أعداد السجلات بناءً على قاعدة البيانات الفعلية.
- اتساق مولدات المعرّفات مع القيم المستوردة.
- وجود نتيجة لكل سجل: أضيف، حُدث وفق قاعدة مسموحة، أُصلح وفق قاعدة معلنة، تُرك وفق قاعدة معلنة، أو يتطلب مراجعة.
- أن التقرير يطابق النتيجة الفعلية ولا يعلن نجاحًا كاملًا مع وجود تعارض إلزامي.

## 8. بوابة الإطلاق

لا يُسمح بالإطلاق إذا:
- فشل أي اختبار مطلوب.
- لم يمكن إثبات التراجع الكامل عند الفشل.
- بقيت علاقات مفقودة أو معرفات متعارضة أو تسجيلات نشطة مكررة.
- كانت نتيجة عملية بعد انقطاع الاتصال مجهولة.
- كان التقرير غير متسق مع البيانات الفعلية.
- لم ينجح اختبار دورة كاملة: إنشاء نسخة، تنزيلها، معاينتها، استعادتها في بيئة معزولة، ثم مقارنة النتيجة المتوقعة بالحالة الفعلية.
