# بحث موارد تصميم واجهات أرض كنعان

**الحالة:** قرارات تصميم أولية موثقة — الاتجاه المؤسسي الفاتح بالكحلي والأزرق، والخط قيد المقارنة بين IBM Plex Sans Arabic وNoto Sans Arabic، والوضع الفاتح افتراضيًا. استراتيجية MCP ما زالت قيد المقارنة. لا يعني ذلك اعتماد مكتبة واجهات نهائيًا أو تثبيت أي حزمة أو خادم MCP.

## الهدف والنطاق

جمع مراجع موثوقة لبناء واجهة عربية RTL حديثة لنظام إدارة الطلاب والدورات والتسجيلات. يجب أن تدعم الواجهة البحث والجداول والنماذج والحالات الفارغة ورسائل الخطأ والتأكيدات والعمليات الحساسة. لا يشمل النطاق أي ميزات مالية.

## اتجاه تصميم مقترح — غير معتمد

- **اللغة والاتجاه:** العربية، وdir=rtl على مستوى التطبيق، مع ضبط اتجاه الحقول وفق نوع المحتوى.
- **المظهر:** الوضع الفاتح هو الوضع الافتراضي. لا يُعد الوضع الداكن ضمن النطاق المعتمد الآن؛ يمكن تقييمه لاحقًا دون تغيير القرار الافتراضي.
- **الخط:** لم يُحسم بعد؛ المقارنة أولًا بين IBM Plex Sans Arabic وNoto Sans Arabic باستخدام عينات عربية وجداول ونصوص صغيرة وأرقام إنجليزية مثل `ST-000123` وتواريخ `YYYY-MM-DD`.
- **الألوان والاتجاه البصري (قرار أولي):** واجهة مؤسسية فاتحة، بخلفيات محايدة وكحلي للهيكل والعناوين وأزرق للعناصر التفاعلية. تبقى قيم الألوان الدقيقة والتوكنات غير معتمدة إلى أن تُختبر نماذج RTL والتباين.
- **التوكنات:** مصدر واحد للقيم الدلالية للألوان والخطوط والمسافات والحواف والظلال والتركيز والحركة، بدل تكرار القيم داخل المكونات.
- **إتاحة الاستخدام:** قياس تباين النص والخلفية وفق WCAG، وعدم الاعتماد على اللون وحده لشرح الحالة، وإظهار حالات التركيز بلوحة المفاتيح.
- **الاستجابة:** جداول قابلة للاستخدام على الشاشات الصغيرة، مع بدائل عرض مناسبة بدل تصغير جدول مكتبي حتى يصبح غير مقروء.
- **النصوص:** مصطلحات عربية ثابتة، وتسميات أزرار مباشرة، ورسائل خطأ تشرح السبب والخطوة التالية، وتأكيد صريح قبل الدمج والاستعادة والاستبدال.

## متطلبات اختيار MCP قبل تفعيله

1. تحديد بيئة التطوير الفعلية والعميل الذي سيشغّل MCP.
2. التحقق من المستودع الأصلي، والنشاط والصيانة، والرخصة، والاعتماديات، وطريقة التثبيت، والصلاحيات، وأي اتصال شبكي أو إرسال بيانات.
3. تجربة الأدوات على بيانات تصميم عامة فقط، وعدم وضع رموز وصول أو أسرار في Git.
4. توثيق طريقة التشغيل محليًا خارج ملفات المستودع العامة إذا احتوت الإعدادات على أسرار.
5. اعتماد MCP لا يعني اعتماد تصميمه أو تثبيت كل المكونات التي يقترحها.

## بوابة إدخال أي مورد إلى المستودع

قبل نسخ كود أو ملفات أو خطوط إلى المستودع:
- مراجعة الرخصة الأصلية وملفات الإشعار ومتطلبات النسبة.
- تفضيل التوثيق والروابط على نسخ مستودعات كاملة.
- عدم إدخال ملفات بناء أو إعدادات شخصية أو مفاتيح أو ملف إعداد MCP يحتوي أسرارًا.
- تثبيت الإصدارات عند بدء التنفيذ وفحص الاعتماديات.
- توثيق المصدر والإصدار والرخصة والملفات التي تم اقتباسها.
- عدم إضافة أداة أو مكتبة لمجرد أنها موجودة في مورد مرجعي.

## الخطوات التالية

1. توثيق الاتجاه المؤسسي الفاتح بالكحلي والأزرق بوصفه قرارًا أوليًا، مع إبقاء قيم التوكنات الدقيقة للمراجعة.
2. مقارنة IBM Plex Sans Arabic وNoto Sans Arabic على عينات موحدة قبل اعتماد الخط.
3. مواصلة مقارنة أدوات MCP، بما فيها MCP الرسمي لـ shadcn/ui والبدائل المذكورة، وفق الصيانة والرخصة والصلاحيات والاعتماديات؛ لا اختيار أو تثبيت في هذه المرحلة.
4. إنشاء مواصفة تصميم داخلية مستقلة تتضمن توكنات الألوان والخطوط والمسافات والحالات.
5. بناء نموذج أولي للوحة الرئيسية وقائمة الطلاب والدورات قبل اختيار جميع المكونات.
6. اختبار التباين ووضوح الخط والأرقام الإنجليزية وتجاوب الجداول.
7. بعد موافقة صريحة فقط، تحديد الموارد التي ستُضاف فعليًا إلى المشروع.

## حدود ما أُنجز

هذا الملف يسجل البحث والمرشحين فقط. لم تُنشأ واجهة تشغيلية، ولم يُثبّت MCP أو أي مكتبة، ولم تُنسخ خطوط أو مكونات من مستودعات خارجية، ولم تُنشأ قاعدة بيانات أو SQL أو migrations.
